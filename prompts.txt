1. Dependency Version Mismatch or Conflict:
The version of ASM (the bytecode manipulation library) that is being pulled in by your
dependencies might conflict with what your code (or other plugins like Checkstyle or
bytecode analyzers) expect. For example, if some component in your project expects
ASM 7.x or 9.x but an older version is available, it may result in a failure to process
classes correctly.
2. Missing Dependency:
It’s possible that the necessary ASM dependency is missing in your module, meaning
that when the code tries to create a ClassReader to inspect a class, it either gets a null or
an improperly populated object.
3. Corrupted or Incompatible Class Data:
In rare cases, if you are processing classes that are generated dynamically or if the class
files are corrupted in some way, ASM might fail to read them, leading to null pointers
when trying to access properties like the super name.

These errors are coming from CDAP’s internal class‐rewriting mechanism—specifically, from
the part that uses ASM to inspect class hierarchies. In your case, when the code tries to
create a ClassReader for java.lang.Object (a system class loaded via the module system, with
a jrt: URL), it fails and returns null. Later, a call to getSuperName() on that null value causes a
NullPointerException.
This is not an error in your own directive or dataset code; it occurs deep inside the CDAP
library (in classes like io.cdap.cdap.internal.asm.Classes and MainClassLoader). In many
cases, this happens because:
• Dataset rewriting is being applied to system classes:
The rewriting logic (which is meant to instrument or intercept user-defined Dataset classes)
ends up being invoked for java.lang.Object and other system classes, which it should
normally ignore.
• Incompatibility with Java’s Module System:
When running on Java 9 or later, the module system (using jrt: URLs) sometimes causes older
versions of ASM or the CDAP rewriting code to fail to read system classes correctly.
• Dependency or Environment Issues:
Your environment might be pulling in an ASM version that isn’t fully compatible with the
module system or the CDAP rewriting mechanism.

Because these errors are coming from internal CDAP components, you have a few potential
workarounds:
1. Disable Dataset Rewriting for Tests:

appropriate system property. (For example, if CDAP checks for
